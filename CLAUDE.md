# CLAUDE.md

P1 Maintenance Dashboard: one-page Top 5 Priority-1 repair tracker for power plants 5, 10, 6, 11 (Thai UI).
Full system doc, work log and roadmap: `docs/SYSTEM.md` (Thai); rules agreed with the team: §8.2.3 there. The user speaks Thai — reply in Thai. User-facing guide: `README.md`.

## Stack & builds
- React 19 + Vite 8, no router, plain CSS (`src/styles.css`, oklch tokens matching the Claude Design source in `project/`).
- One UI, three data backends chosen at build time by `__BACKEND__` (see `src/lib/store.js`):
  - `npm run build` → `local` (localStorage) → GitHub Pages via `.github/workflows/deploy.yml` (pushes `dist/` to `gh-pages`).
  - `npm run build:server` → `api` → Cloudflare Worker (`worker/index.js`, `wrangler.jsonc`) or Node (`server/index.js`).
  - `npm run build:artifact` → `artifact` → single file for the claude.ai artifact (React 18 UMD from cdnjs).
- Server logic shared by Worker and Node: `server/core.js` (validation + Postgres, one `docs` table) and `server/api.js` (router + permissions).

## Conventions
- WO Backlog: CMMS "List of Work Orders" export parsed in the browser (`src/lib/cmms.js`), stored as one snapshot doc `backlog/current`,
  shown in `components/Backlog.jsx` ("⬇ ดาวน์โหลด Excel" exports the filtered list via `buildBacklogWorkbook` + App `saveFile`); Top 5 jobs link to it by WO number. A second page (`PageTabs` in App, hash `#wo-dashboard`) shows `components/BacklogDashboard.jsx` — the team's weekly Excel summary computed by `backlogDashboard()` in `src/lib/backlogDash.js` from the same open rows (KPIs, status groups, teams, aging bands, plants, team × status, next approvers, oldest 10); stack/legend order `STACK_ORDER` keeps neighbouring colours distinguishable. Uploads merge by WO (`mergeBacklog`: new + changed
  status, keeps prevStatus/statusSince/changedAt/seenAt; missing WOs kept and flagged unless removed).
- Daily CMMS report: every backlog upload folds `dayEvents` (opened = Actual Start is the day — what the team calls "เปิดงาน", shown in tiles/tables/LINE; new = WO not in the previous file / started = into APPR·INPRG·REWORK or Actual Start = today / finished / closed, as [wo, plant, team]) and `openSnapshot` (per "plant|team" open + age buckets) into `stats/<YYYY-MM-DD>` via `foldDayStats` (unions by WO, so repeated uploads in a day never double count). Server does it inside `saveBacklog`; local/artifact stores do it client-side. The CMMS export drops closed WOs, so with `MISSING_IS_CLOSED` (cmms.js, true) a WO present in the previous file but missing from the new one counts as CLOSED: listed in `assumed` and in `closed` (undone via `back` if it reappears the same day); `effGroup(r, latest)` treats missing rows as closed everywhere; `closedStatus` = closed from Status column L. Event tuples carry [wo, plant, team, at, flag] (new WOs: flag = 1 when its Actual Start is the upload day = "แทรกระหว่างวัน"; other events: 1 if after the day's first upload); `statTotals` gives `inserted`, `roundTotals` the per-upload breakdown. Upload option "Baseline" (`baseline: YYYY-MM-DD`) wipes `stats` and writes `baselineStats` for that day (file name date via `dateFromFileName`). Team = `teamOf(WO_Worklocation)`: WL5112/WL5121 MECH, WL5115 ELEC, WL5118 AUTO, WL5122/WL5123 EMER. Both report panels filter by a multi-select WO_Worklocation picker (`components/WlSelect.jsx`, value = array of codes, `wlOptions`, `scopeMatch(f, team, wl)`: ''/[] all, team key, WL code or an array); stats tuples carry the code at index 5 and snapshot keys are `plant|team|wl` since Oct 2026 (older events resolved via the backlog `wlOf`, the latest day's legacy snapshot rebuilt from the backlog). UI `components/Report.jsx`, API `GET /api/stats`.
- WO history (`wohist/current`, one doc): yearly CMMS export of every P1 WO (status `CLOSE` = closed) imported via "นำเข้าฐานข้อมูลประวัติ" (`PUT /api/wohist`, rows from `histRowsFrom`: wo, plant, team, status, as=Actual Start, af=Actual Finish, ts, desc). Every daily backlog upload applies the `applyDailyToHist` rules (server: `syncHist` does it in one SQL statement so the Worker never parses the ~0.5 MB doc — Workers Free ≈10 ms CPU; local store: JS). Import is sent in parts of 500 (`part`, `last`; part 0 replaces, later parts append in SQL) and `GET /api/wohist` passes `data::text` through (`raw`): open WOs take the file's status/dates, new ones are added, open WOs missing from the file close with af=today, est=true; closed rows never reopen. Order guard: the doc keeps `asOf` (latest date in the imported file, `GREATEST`-ed by each sync); daily uploads send `fileDate` (`fileAsOf`: file-name date, else latest date in the rows) and `syncHist` skips when `fileDate < asOf` → `PUT /api/backlog` returns `hist: none|skipped|synced` (toast in App.jsx). Daily panel counts when the file changes, history counts by Actual Start/Finish, so a WO closed today with an old Actual Finish lands in an earlier month (notes in both panels). `components/HistoryReport.jsx` (today / 7 days / month / since Jan; WMATL counted as "รออะไหล่", separate from "รอเริ่ม") via `histTotals`/`histSeries`: opened = Actual Start in range, closed = CLOSE with Actual Finish in range, backlog = started and not closed by the end. Not supported in the artifact build.
- LINE (`server/line.js`, optional secrets `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_TO`, `LINE_CHANNEL_SECRET`): summary push after every `PUT /api/backlog` = per-plant round report from `src/lib/roundReport.js` (09:30 start / 16:30 end of work by upload hour; opened · inserted · finished-or-closed · open ± prev day, then the new-WO list with status, inserted first, max 20; also the Report "คัดลอกรายงานรอบ" button and the per-plant table) (response `line: sent|failed|off`, never fails the upload), `POST /api/line/test`, webhook `POST /api/line/webhook` (signature-checked, skips Access; replies to "สรุป"/"id" — replies cost no quota), cron reminders 09:45/16:45 Thai Mon–Sat in `wrangler.jsonc` → `scheduled()` → `remindIfNoUpload`. `LINE_API_BASE` overrides the API host for local mock tests.
- One Top 5 job per WO number (form, stores, server `duplicate_wo`); "ลบงานซ้ำ" uses `findDuplicates` in `src/lib/dedupe.js`. Status groups are the team's (see docs/SYSTEM.md §8.1).
- No `EDIT_PASSWORD` (and no Access editor list) → API is view-only (`setup: 'no_password'`) unless `ALLOW_OPEN_EDIT=true`.
- Two ranked lists per plant (`LISTS`/`listOf` in `src/lib/data.js`: job `list` = `risk` (BD, default for old jobs) | `daily`); each shows the first `TOP_N`=5 open jobs by rank, extras/done fold away. The daily tab also lists `cmmsToday` (view.js: plant backlog rows present in the latest file with Actual Start = today) with tap-to-expand details and "＋ เพิ่มเข้ารายการงานประจำวัน" (`trackWo(row, 'daily')`); none → message asking the team to add manually. ▲▼ or drag (pointer events on the rank badge / ⠿ grip, mouse + touch) save the list order via `reorderJobs` (`POST /api/jobs/rank`).
- Free tiers (docs/SYSTEM.md §8.4): the api store polls `/api/version` every 15 s only while the tab is used; after 10 min without input it polls every 30 min so Neon's free compute (100 CU-h/month) can suspend. Keep new server work within Workers Free (10 ms CPU) and LINE's 300 pushes/month.
- Safety cap `MAX_JOBS_PER_PLANT`=30 (both lists), enforced in UI, all stores, server (`plant_full`) and Excel import.
- CMMS export times are Thai wall clock; read-excel-file returns them as UTC fields, so `thaiDay` takes the UTC date as-is (never add +7 h).
- Dates are `YYYY-MM-DD` strings; "today" is Thai time (UTC+7). Job buckets: done / stuck (pending or overdue) / doing.
- Imports without a `photos` key must keep existing photos (all three backends honour this); `replace: true` deletes jobs not imported.
- Error details returned to the browser must never contain the database URL (see `reason()` in worker, api.js).
- Commit messages end with the Co-Authored-By / Claude-Session lines used in history.
